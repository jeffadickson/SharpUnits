## Executable diagnostics and directed faults

Run from the existing checkout with the installed SDK/runtime:

```powershell
$repo=(Get-Location).Path
if(!(Test-Path -LiteralPath $repo -PathType Container)){throw 'Select the SharpUnits checkout'}
$dotnet=Join-Path $env:USERPROFILE '.dotnet/dotnet.exe'
& $dotnet run --file tools/VerificationAudit.cs -- ../tools-runtime/python/python.exe
# Exit 1 is intentional while findings remain; inspect verification-audit-results.json.
```

The C# diagnostic helper uses the real existing Python verification CLIs and real CLR domain objects. It records three controls and 11 unsafe acceptances/observation witnesses. It is a findings collector for the stated historical baseline, not a qualification gate. Current verifier source hashes identify the executed tools. Positive-control or historical-hash failures invalidate execution with exit 2; open findings return exit 1. Even a clean probe set requires a separate qualification decision. It does not repair the tools, generate passing regression-test claims, or copy the observed implementation into an expected-result oracle. `PublishAot=false` is explicit for this JSON diagnostic helper; no native compilation or helper code-coverage claim is made.

Directed ordering faults use an isolated `git archive` of the audited commit, leaving the working checkout unchanged. The control runs the two existing adversarial ordering facts. One replay replaces `steps.Concat(argument.steps)` with `argument.steps.Concat(steps)`; another reverses the transformed unit's parent/operation composition. Source is restored within the isolated snapshot after each replay. Actual pass/fail results, snapshot path and log hashes are retained in the execution record. These are explicit semantic fault replays, not a custom mutation engine or a replacement for Stryker.

The historical expectations remain retained. A future repair must first make the corresponding negative witnesses fail against the old verifier, then pass against the corrected verifier, and rerun affected corpora. Merely changing an expectation or normalizer to obtain agreement is unacceptable.
